학교 학습 사이트를 혼자 운영하면 서버를 쉬게 하거나 백업할 시간이 따로 있어야 합니다. 저는 처음에 밤 10시부터 아침 7시까지 바깥 접속을 막았습니다. 그런데 학생들이 밤에 과제를 하는 일이 생각보다 많아서, 이번 주에 점검 시간을 **매일 새벽 5시부터 6시까지 한 시간**으로 줄였습니다.

숫자 두 개만 바꾸면 될 줄 알았습니다. 그런데 막상 고쳐 보니 시간 계산에서 놓치기 쉬운 곳이 네 군데 있었습니다.

## 1. '자정을 넘는 창'과 '넘지 않는 창'을 함께 다루기

예전 점검은 22시에 시작해 다음 날 7시에 끝났습니다. 그래서 코드에는 "시작 시각보다 늦거나, 끝 시각보다 이르면 점검 중"이라는 조건이 들어 있었습니다. 이 조건은 5~6시처럼 자정을 넘지 않는 창에서는 틀린 답을 냅니다. 오후 3시도 "5시보다 이르다"는 조건에 걸리기 때문입니다.

그래서 시각을 비교하는 대신 **실제 날짜가 붙은 시작·끝 시각**을 먼저 구하도록 바꿨습니다. 아래는 원리만 남겨 새로 쓴 예시 코드입니다.

```python
from datetime import datetime, time, timedelta

def window(now, s, e):
    hours = (e - s) % 24 or 24
    start = datetime.combine(now.date(), time(s))
    prev = start - timedelta(days=1)
    if now < start and now < prev + timedelta(hours=hours):
        start = prev   # 어제 시작한 창이 아직 안 끝남
    return start, start + timedelta(hours=hours)
```

핵심은 `(e - s) % 24`입니다. 5~6이면 1시간이고, 22~7이면 `(7 - 22) % 24`라서 9시간이 됩니다. 길이를 알면 "어제 시작한 창이 아직 진행 중인가"만 따로 확인하면 됩니다. 예를 들어(지어낸 시각) 22~7 설정에서 새벽 2시라면 어제 22시에 시작한 창 안에 있고, 아침 8시라면 오늘 22시에 시작할 창을 돌려줍니다.

## 2. 과제 마감이 점검 시간 안에 있으면?

학생이 마감 직전에 제출하려는데 사이트가 닫혀 버리면 안 됩니다. 그래서 점검 창 안에 과제 마감이 있으면 **가장 늦은 마감 시각 다음 정시부터** 막도록 했습니다.

```python
def real_start(ws, we, deadlines):
    inside = [d for d in deadlines if ws <= d < we]
    if not inside:
        return ws
    top = max(inside).replace(minute=0, second=0,
                              microsecond=0)
    return top + timedelta(hours=1)
```

점검이 한 시간뿐이라서 5시 30분 마감이 하나 있으면 시작이 6시로 밀리고, 그날은 점검을 건너뛰게 됩니다. 저는 이 결과가 맞다고 봤습니다. 서버는 다음 날 쉬어도 되지만, 학생의 마감 시간은 그날 하루뿐이니까요.

이때 하나 조심할 점이 있습니다. 데이터베이스에는 마감 시각이 **UTC로 저장**되어 있고, 점검 시간은 한국 시각으로 정합니다. 비교하기 전에 창의 시작·끝을 UTC로 바꾸고, 결과는 다시 한국 시각으로 바꿔야 합니다. 이걸 빠뜨리면 9시간이 어긋나서 엉뚱한 마감을 기준으로 점검 시간을 계산합니다. 또 요청이 들어올 때마다 데이터베이스를 조회하지 않도록 계산 결과를 1분 동안 기억해 두었습니다.

## 3. 화면 안내 문구도 시간에 맞추기

예전 안내 문구는 '밤 10시'처럼 밤을 기준으로 쓰여 있었습니다. 점검 시간이 새벽으로 바뀌면서 시각을 말로 바꿔 주는 작은 함수를 따로 만들었습니다. 6시 전이면 '새벽', 12시 전이면 '아침', 그 뒤는 '오후'와 '밤'으로 나눕니다. 마감 때문에 시작이 자정까지 밀리면 '24시'로 보여 줍니다. 별것 아닌 것 같지만, 학생이 "새벽 5시부터 아침 6시까지 점검해요"라는 문장을 읽고 바로 알아들을 수 있어야 문의가 줄어듭니다.

## 4. 쉬는 요일은 '시작하는 날' 기준으로

특정 요일에 점검을 쉬게 하는 설정도 두었는데, 여기서도 기준을 정해야 했습니다. 자정을 넘는 창이라면 토요일 밤 점검이 일요일 새벽까지 이어집니다. 저는 **창이 시작하는 날의 요일**로 정했습니다. 앞에서 창의 시작 시각을 날짜까지 붙여서 구해 두었기 때문에 `start.weekday()` 한 줄로 해결됐습니다.

## 전체 코드

위의 네 가지를 한 파일로 모았습니다. 실제 사이트에서는 마감 시각을 데이터베이스에서 읽고 1분 동안 기억해 두지만, 여기서는 직접 실행해 볼 수 있도록 마감 목록을 함수에 넘기게 바꿨습니다. 파이썬만 있으면 그대로 돌아갑니다.

```python
from datetime import datetime, time, timedelta, timezone

KST = timezone(timedelta(hours=9))
START, END = 5, 6    # 점검 시각(한국 시각)
SKIP_DAYS = set()    # 쉬는 요일(월=0 … 일=6)


def window(now):
    """지금 진행 중이거나 다음에 올 점검 창 [시작, 끝)"""
    hours = (END - START) % 24 or 24
    start = datetime.combine(now.date(), time(START), KST)
    prev = start - timedelta(days=1)
    if now < start and now < prev + timedelta(hours=hours):
        start = prev    # 어제 시작한 창이 아직 안 끝남
    return start, start + timedelta(hours=hours)


def real_start(ws, we, deadlines_utc):
    """창 안에 마감이 있으면 가장 늦은 마감 다음 정시"""
    lo = ws.astimezone(timezone.utc)
    hi = we.astimezone(timezone.utc)
    inside = [d for d in deadlines_utc if lo <= d < hi]
    if not inside:
        return ws
    last = max(inside).astimezone(KST)
    top = last.replace(minute=0, second=0, microsecond=0)
    return top + timedelta(hours=1)


def in_maintenance(now, deadlines_utc):
    ws, we = window(now)
    if ws.weekday() in SKIP_DAYS:   # 시작하는 날 기준
        return False
    return real_start(ws, we, deadlines_utc) <= now < we


def hour_label(h):
    """안내 문구용: 5 → '새벽 5시'"""
    if h in (0, 24):
        return "24시"
    if h < 6:
        return f"새벽 {h}시"
    if h < 12:
        return f"아침 {h}시"
    if h == 12:
        return "낮 12시"
    if h < 18:
        return f"오후 {h - 12}시"
    return f"밤 {h - 12}시"


# 확인해 보기(날짜·마감은 지어낸 값)
def kst(d, h, m=0):
    return datetime(2026, 11, d, h, m, tzinfo=KST)

due = [kst(30, 5, 30).astimezone(timezone.utc)]
print(in_maintenance(kst(29, 5, 10), due))   # True
print(in_maintenance(kst(30, 5, 10), due))   # False
print(in_maintenance(kst(29, 15), due))      # False
print(hour_label(START), hour_label(END))    # 새벽 5시 새벽 6시
```

마지막 세 줄을 보면, 11월 29일 새벽 5시 10분에는 점검 중이지만 30일에는 5시 30분 마감(지어낸 값) 때문에 시작이 6시로 밀려서 점검하지 않습니다. `START, END = 22, 7`로 바꿔서 새벽 2시와 아침 8시를 넣어 보면 1번에서 말한 자정을 넘는 창도 확인할 수 있습니다.

## 정리: 시각이 아니라 '구간'으로 생각하기

이번 일에서 배운 것은 하나입니다. "지금 몇 시인가"를 비교하지 말고, **날짜가 붙은 구간 [시작, 끝)을 먼저 만들고** 그 안에 지금이 들어가는지 보면 됩니다. 이렇게 하면 자정을 넘는 경우, 마감 때문에 시작이 밀리는 경우, 쉬는 요일을 정하는 경우를 모두 같은 방법으로 처리할 수 있습니다.

수업에서 조건문을 가르칠 때도 좋은 예제가 될 것 같습니다. "편의점 영업시간이 22시~7시일 때 지금 문을 열었을까?" 같은 문제를 내 보면, 많은 학생이 처음에는 `22 <= h <= 7`이라고 씁니다. 왜 틀렸는지 함께 따져 보면 경계값과 구간을 다루는 연습이 됩니다.
